# S6: Paid GitHub gates on a private repo (account `passpier`, Free plan)

Probed 2026-10-14 through the REST API on a private probe repo, `passpier/rnship-s6-probe`. It's safe to delete.

| Feature | Result | Evidence |
|---|---|---|
| Branch protection | **Unavailable** | `PUT /branches/main/protection` returns 403 "Upgrade to GitHub Pro or make this repository public" |
| Rulesets | **Unavailable** | `POST /rulesets` returns the same 403 |
| CODEOWNERS enforcement | **Unavailable** | It needs a branch-protection or ruleset rule (`require_code_owner_review`), and both are 403 |
| Environment with required reviewers | **Unavailable** | `PUT /environments/production` with `reviewers` returns 422 "ensure the billing plan supports the required reviewers protection rule" |
| Environment without protection rules | Available | `PUT /environments/staging` returns 200 |
| Environment secrets | **Available** (this contradicts the plan, §0.1) | `gh secret set --env staging` succeeded |
| Repo secrets | Available | `gh secret set` succeeded |
| Forking a private repo | Allowed (`allow_forking: true`) | This enables fork-based PRs for the machine account (see S0) |
| Actions minutes for private repos | **Not checked** | The billing API needs the `user` scope (`gh auth refresh -s user`). The published Free allowance is 2,000 min/month. |

## Consequences for the plan
- D1 holds: no GitHub feature on Free can be the gate for a private app repo, which confirms §0.1.
- Environment secrets do work on Free, but without required reviewers anyone with Write can run a job that uses them. So they offer no protection over repo secrets, and the §1 rule stays: `EXPO_TOKEN` goes only into push-to-`main` jobs.
- **Without branch protection, any collaborator with Write can push to `main` and merge PRs.** The machine account must therefore not hold Write on app repos. S0 tests the alternative: Read access plus PRs from a fork.
