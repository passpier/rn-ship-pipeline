## What changes in the plan
1. **The orchestrator runs validation itself.** The design assumed ralphex runs the `## Validation Commands` (X8). It doesn't, so after every executor run the orchestrator's `validating` state re-runs each task's commands under `rnship sandbox run --`. The plan still lists them, so Claude runs them too as feedback.
2. **Exit codes say almost nothing** (X1). The adapter classifies a run from the stderr `error:` line and the progress footer. It never sends SIGQUIT (an abort exits 0); it stops a run with SIGTERM to the process group, with stdin set to `/dev/null`.
3. **Reset times and denials come from our own transcript** (X4, X7). `claude_command` is a shim that tees the stream-json to a file and checks `system/init` as it streams. If the guard plugin is missing, it kills claude and prints `RNSHIP: plugin_missing`, which is in `claude_error_patterns`, so the run fails closed. The adapter reads `rate_limit_event`, `permission_denials`, usage and the model ID from that transcript.
4. **The orchestrator owns retries** (D2): `task_retry_count = 0`, `wait_on_limit = false`, `move_plan_on_completion = false`, `external_review_tool = none`. Config comes from a per-run `--config-dir`, never the app repo's `.ralphex/`.
5. **No Docker wrapper** (X13). ralphex runs directly as `rnship-agent`.
6. **A crashed run counts for nothing** (X16). The orchestrator resets the worktree to the batch's start commit, and the adapter reports no completed tasks for `plugin_missing`, so nothing an unguarded session committed survives. The diff check and D1 still back this up.
